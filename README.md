# GS1 Marking Code (TCP Server / Client)

Два консольных приложения на **C# / .NET 10**, взаимодействующих по протоколу
TCP:

- **`Gs1Marking.Server`** — TCP-сервер, генерирующий коды маркировки в формате GS1.
- **`Gs1Marking.Client`** — TCP-клиент, принимающий коды и сохраняющий их в файл.

Оба приложения написаны асинхронно (`async`/`await`), корректно обрабатывают
подключение, отключение и повторное подключение, а также защищены от потери и
«склеивания» сообщений при потоковой передаче.

## Структура проекта

```
.
├── src/
│   ├── Gs1Marking.Contract/          # Общая библиотека
│   │   ├── Gs1/                    #   Генератор GS1-кодов + контрольная цифра
│   │   └── Protocol/               #   Фрейминг сообщений (length-prefix)
│   ├── Gs1Marking.Server/          # TCP-сервер
│   └── Gs1Marking.Client/          # TCP-клиент
├── tests/
│   └── Gs1Marking.Tests/           # Unit- и интеграционные тесты (xUnit)
└── Gs1Marking.sln
```

Ключевые классы:

| Класс | Проект | Назначение |
|-------|--------|------------|
| `Gs1CodeGenerator` | Contract | Генерация кода `(01)…(21)…(17)…(10)…` |
| `Gs1CheckDigit` | Contract | Расчёт/проверка контрольной цифры GTIN-14 |
| `MessageFraming` | Contract | Потоковое чтение/запись с префиксом длины |
| `MarkingCodeServer` | Server | Циклы приёма подключений и генерации кодов |
| `ClientConnection` | Server | Одно подключение: очередь исходящих + детект отключения |
| `MarkingCodeClient` | Client | Подключение, приём, авто-переподключение |
| `MarkingCodeFileWriter` | Client | Потокобезопасная запись кодов в файл |

## Запуск сервера

```bash
dotnet run --project src/Gs1Marking.Server
```

Параметры командной строки:

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `--port <n>` | `5000` | TCP-порт |
| `--interval-ms <n>` | `500` | Период генерации кода, мс |
| `--bind <address>` | `127.0.0.1` | Адрес для прослушивания |
| `--help` | — | Справка |

Пример:

```bash
dotnet run --project src/Gs1Marking.Server -- --port 7410 --interval-ms 250
```

Сервер генерирует код каждые 500 мс и рассылает его **всем** подключённым
клиентам. Подключение, отключение и повторное подключение обрабатываются
автоматически; остановка — по `Ctrl+C`.

## Запуск клиента

```bash
dotnet run --project src/Gs1Marking.Client
```

Параметры командной строки:

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `--host <host>` | `127.0.0.1` | Адрес сервера |
| `--port <n>` | `5000` | Порт сервера |
| `--output <path>` | `marking-codes.txt` | Файл для сохранения кодов |
| `--reconnect-ms <n>` | `2000` | Задержка между попытками переподключения, мс |
| `--help` | — | Справка |

Пример:

```bash
dotnet run --project src/Gs1Marking.Client -- --host 127.0.0.1 --port 7410 --output codes.txt
```

Каждый принятый код дописывается в файл отдельной строкой. При разрыве
соединения клиент логирует ошибку и автоматически переподключается. Остановка —
по `Ctrl+C`.

Рекомендуемый порядок запуска: сначала сервер, затем клиент.

## Формат кода маркировки GS1

Сервер генерирует код в человекочитаемой форме (HRI):

```
(01)01234567890128(21)SERIAL12345(17)260430(10)BATCH01
```

| AI | Содержимое | Описание |
|----|------------|----------|
| `(01)` | GTIN-14, 14 цифр | Глобальный номер товара с контрольной цифрой |
| `(21)` | серийный номер, 10 симв. `[A-Z0-9]` | Серийный номер единицы |
| `(17)` | дата, `YYMMDD` | Срок годности |
| `(10)` | номер партии, 6 симв. `[A-Z0-9]` | Номер партии |

Контрольная цифра GTIN-14 рассчитывается по стандартному алгоритму GS1
(веса 3/1) и проверяется модульными тестами.

## Протокол передачи

TCP — потоковый протокол, он **не сохраняет границы сообщений**: пришедшие байты
могут быть разрезаны или склеены. Поэтому поверх TCP используется
**префикс длины**:

```
[ 4 байта: длина сообщения (big-endian) ][ N байт: UTF-8 payload ]
```

`MessageFraming` читает данные циклом «до полного заполнения буфера»
(`ReadExactlyAsync`), поэтому корректно обрабатывает частичные чтения и не
теряет/не склеивает сообщения. Также накладывается верхний предел на длину
сообщения для защиты от некорректных префиксов.

## Тесты

```bash
dotnet test Gs1Marking.sln
```

Покрываются:

- **`Gs1CheckDigit`** — расчёт и проверка контрольной цифры GTIN-14.
- **`Gs1CodeGenerator`** — формат кода, валидность GTIN, уникальность.
- **`MessageFraming`** — round-trip, несколько сообщений подряд, частичные
  чтения, обрыв сообщения, некорректная длина.
- **`MarkingCodeFileWriter`** — дописывание кодов в файл.
- **`ServerIntegrationTests`** — сквозной тест: реальный сервер на ephemeral-порте
  отдаёт корректный GS1-код реальному `TcpClient`.

## Ключевые решения

- **Асинхронность.** Все операции ввода-вывода (`AcceptTcpClientAsync`,
  `ConnectAsync`, `ReadAsync`/`WriteAsync`, запись в файл) — `async`/`await` без
  блокирующих вызовов.
- **Отделение генерации от сети (сервер).** Каждое подключение имеет собственную
  неограниченную очередь (`Channel<string>`) и выделенный писатель; медленный
  клиент не тормозит генерацию кодов.
- **Детект отключения.** Отдельная задача-читатель на сервере фиксирует закрытие
  соединения (чтение 0 байт), а клиент обрабатывает `EndOfStreamException` и
  переподключается.
- **Освобождение ресурсов.** `IAsyncDisposable` на сервере, клиенте, подключении
  и файловом писателе; остановка через `CancellationToken` (Ctrl+C).
- **Чистая архитектура.** Общий код (генератор и протокол) вынесен в библиотеку
  `Gs1Marking.Contract` и покрыт модульными тестами.
